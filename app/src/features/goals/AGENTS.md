# goals

Node-owned Goals + KPIs presentation. The reusable measurement engine and the wire contract (`GoalsProgressSchema`, `KpiAssessmentSchema`, `MetricHistorySchema`) live in `@cogni-dao/metrics/contracts`; this feature owns product composition, the read-only goal/EDO projection (`services/`), and the Goals view (`components/GoalsBoard`).

## UI rules

- `GoalsBoard` is reusable: no Knowledge-route imports. Knowledge mounts it only on `?mode=goals`, so its 30s poll (`refetchIntervalInBackground: false`) runs only while that tab is selected. The entry page mounts it with `goalId`.
- Status comes from `assessKpi` only. The UI never re-derives it, and never lets the chart range change it. Every status shows a symbol and a word (`lib/presentation.ts` `STATUS_META`); color is redundant. Every `KpiReason` maps to one plain sentence in `REASON_TEXT`, and the type system enforces that the map is exhaustive.
- Unknown is not zero. A missing reading says so; delayed and failing values are shown muted and labeled "last good". After a failed refresh, the board keeps the last data and labels it "not current" under one `role="alert"`.
- Gaps stay gaps. Sparklines and the history chart break at every non-ok bucket (`connectNulls={false}`). The newest reading after the last closed bucket is plotted as its own point, never carried into a bucket. "Not yet measured" means no completed reading: it is shaded only before a start proven by the 400 × 1w probe, and never past `history.to`. Any other non-ok run is a gap (missing = 45° hatch, failed = cross-hatch).
- The hero speaks for the assessment: "Latest", "Last good", "Final" (met/missed) or "At deadline" (evaluating) plus the time. The range label lives on the chart title and toggle, never beside the hero, and the range never changes the hero or the pill.
- The row sparkline is a gradient area with an end dot (no target line; the bullet shows the target). A goal with no bound metric shows no sparkline. The bullet has a rounded track, a target tick and a chart-1 value bar.
- Charts use Recharts 2.15.4 through `ChartContainer`; no hand-rolled chart SVG. Raw SVG lives only in `components/chart-defs.tsx` (the `<defs>` paint servers). Recharts drops custom child components, so a chart's direct children are Recharts elements, `chartDefs(ids)` or arrays from plain functions called inline. Ids come from `useId` stripped to `[\w-]`. Every Area, Line and Bar sets `isAnimationActive={false}` (animation hides dots); hidden dots return a keyed Fragment.
- The history chart is a `figure` with a visible title and an `sr-only` summary that states values, target, gaps and pace. The chart surface (accessibilityLayer, a tab stop) has `aria-labelledby`/`aria-describedby` and a `focus-visible` outline in foreground ink (≥ 3:1 in both themes) that needs `outline-solid` under Tailwind 4. Chart labels never collide: the target label moves to the right edge near the floor, and the "Not yet measured" label is clamped to its shaded span or hidden. "Measured since" uses the range's resolution (a time on hourly ranges, a date on daily ones). Small marks sit in a `div role="img"` with an `aria-label` that states values and the target. The readings table is the keyboard and screen-reader path to evidence. Numbers use `tabular-nums`. Operational IDs stay behind "Inspect" links.

Read the canonical complete active-goal list. Do not introduce goal limits or infer EDO outcomes from thresholds. Predictions keep fixed baselines and deadlines. Never bridge missing history, compare changed definitions, invent expected values, or present stale readings as current. The UI only reads; the existing worker computes. This feature must not import bootstrap, app or adapter code.

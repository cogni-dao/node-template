# node-declarations

Published `@cogni-dao/node-declarations` owns the node-side check of a sovereign node's secret declarations (bug.5254): the same two passes the operator's node-deploy verb runs, so a node learns of a bad declaration in its own pull request instead of at deploy.

Public surface (`.`): `checkNodeDeclarations({ repoSpecText, catalogText, nodeSlug })` returns `{ ok, issues }` (each issue is `{ file, code, path, message }`); `findRetiredSecretRefs` and `readServiceNames` (raw-YAML reads of `.cogni/repo-spec.yaml`); `RETIRED_SECRET_REFS_MESSAGE`; and the secrets-catalog contract (`parseNodeSecretsCatalog`, `catalogSecretKeysFor`, `SecretsCatalogError`, the entry and file Zod schemas, `NODE_SECRETS_CATALOG_PATH`). The `node-declarations-check --repo-root <dir> --node-slug <slug>` executable reads `.cogni/repo-spec.yaml` and `.cogni/secrets-catalog.yaml` (an absent catalog is an empty catalog), prints issues, and exits 0 (ok), 1 (issues), or 2 (bad arguments). `--node-slug` is required: pass the repo-spec `intent.name`, never the repository name.

What it checks: pass 1 is the shared catalog entry schema. Pass 2 is the sovereign-node policy (source `human` or `agent`, generator `hex` or `base64` only; no operator-only fields; `service` is this node; every `workloads` name is a repo-spec service). It also refuses a retired `secret_refs` at the top level or on any `deployment.services[*]`, even as `[]`. Service names come from `deployment.services[].name`, or `["app"]` when there is no `deployment` block (the operator's legacy default). **Not checked:** deploy pass 3 (substrate-reserved, fleet-inherited and off-cluster keys). That is operator data and runs only at deploy. A passing check is not a promise that the deploy will pass.

`src/secrets-catalog.ts` is a byte-for-byte copy of the operator's `packages/repo-spec/src/secrets-catalog.ts`. Do not edit it here. Change the contract in the operator first, copy the file across, and bump this package's version. The retired-`secret_refs` message is the operator's `RETIRED_SECRET_REFS_MESSAGE`, identical text. Leaf package: pure checks, no app, container, env, network or framework imports; only `src/cli-run.ts` and `src/cli.ts` read files. Dependencies are `yaml` and `zod` ^3 (the operator copy's major). Refusals name codes, paths and keys, never a file's text or a value (NO_SOURCE_ECHO). The issue codes, the message text, the CLI flags and exit codes are a published contract: changing any is a version bump. Prove packed JavaScript and declarations in a clean consumer.
